# Content performance (offers and events)

Owner insights (doc 74) measured the website as a whole. This slice adds per-item figures.

- **Counting.** `ContentPageView` (client) posts `{kind, itemId, source}` to `POST /api/content-view` when a non-demonstration offer or event page opens. The server reads the owning business from the item itself, never from the request, and counts only active offers, active or cancelled events, of published, non-demo businesses. Only a coarse traffic-source label is stored (never the referrer address); the visitor signal is hashed. Rows are `business_activity_event` with type `offer_view` or `event_view` and `metadata = {itemId}`.
- **Reporting.** `getContentPerformance` (owner insights, behind the existing `canUserAccessBusiness` gate) returns views for the chosen period and all-time saves per listed offer and event; a failed read is `null` so it never reads as "nobody looked".
- **Migration 0071** only widens the activity-type CHECK (additive; old code keeps working, new code before migration fails safe because insert errors are swallowed).
- **Slice 2 (migration 0075).** Business updates (`update_view`, counted for published updates) and catalogue entries (`catalogue_view`) join offers and events. A catalogue entry lives inside a business's lists, so its beacon also sends the business slug; the server credits the view only if it finds that entry in that published, non-demo business's public lists. The insights panel lists "Updates" and "Catalogue" groups (no saves column: residents cannot save them). Repeat opens of the same item by the same visitor within 30 minutes count once (server side, on the hashed visitor signal), so refreshes no longer inflate figures. The beacon route allows 40 posts a minute per visitor signal (in-memory, per instance) and answers 429 beyond that. Migration 0075 only widens the activity-type CHECK, so old code keeps working.
- **Known limits.** Counts still include bots, and the de-duplication and throttle are per server instance for the throttle and per visitor signal (address plus browser) for de-duplication, so visitors sharing both count once. `/api/business-activity` still has no rate limit. Welsh plural forms for "golwg" are first-draft.
